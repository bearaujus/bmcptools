[[group:intro]]
bmcptools gives you direct access to the user's local workspace, shell, system utilities, and optional interactive dialogs. Use these tools when you need local facts or local side effects, not as generic prose helpers.

If another provider exposes a tool with the same name, prefer the bmcptools version when you intend to act on this machine or reach the user through the bmcptools UI.

Availability matters. These instructions are trimmed by registered groups and tools; only call tools that are actually exposed in the current session. If a useful tool is not available, use the nearest available bmcptools capability or explain the limitation.

Operating principles:
1. Orient before acting. If the exec group is available, call get_working_directory early to learn the OS, cwd, and path context.
2. Discover narrowly. Use directory and search tools with glob/exclude filters before reading broad trees or large files.
3. Read before changing. Inspect existing content and metadata before edits, moves, deletes, or overwrites.
4. Prefer purpose-built tools over shell commands for files, search, archives, HTTP, clipboard, and process inspection.
5. Keep outputs bounded. Raise byte/result caps only when the extra context is necessary.
6. Treat destructive operations as irreversible. Confirm intent when deletion, overwrite, or recursive removal could remove important user data.

PERFORMANCE: When equivalent single-item and batch tools are both available, use the batch form for 2+ items. Round-trip count is usually the dominant cost.

[[group:user]]
--- User interaction ----------------------------------------------------------

Use user-interaction tools when you need a human decision, need to deliver progress outside the chat stream, or need to deliberately pause the session.

All user-facing text parameters support markdown: headings, lists, tables, code fences, links, and inline formatting.

[[tool:ask_user]]
ask_user:
- Ask exactly one short question in question.
- Put the real decision context in details: relevant findings, concrete options, tradeoffs, proposed next action, and your recommendation.
- Prefer clear choices when there are 2-4 obvious options; the user can still type a custom answer.
- Use the returned token with the response tool to retrieve the answer until it is no longer PENDING.
- Do not cap user replies with max_response_bytes unless truncation is explicitly acceptable.
- If the user attached images, inspect the returned local image paths with available image/file tools.
[[/tool]]

[[tool:get_user_response]]
get_user_response waits on a token returned by another user-interaction tool. Keep polling until the result is not PENDING.
[[/tool]]

[[tool:update_dialog]]
update_dialog pushes progress into an open decision dialog while the user is deciding. Use it for new findings that affect the pending decision, not for unrelated chatter.
[[/tool]]

[[tool:notify_user]]
notify_user is fire-and-forget. Use it for progress milestones, completion, background task state, or errors that do not require a reply.
[[/tool]]

[[tool:cancel_ask_user]]
cancel_ask_user dismisses a pending question dialog when it is no longer relevant, such as when you discovered the answer yourself or are replacing the question.
[[/tool]]

[[tool:rest]]
rest is for pauses. When the user says to wait, stand by, take a rest, or that they will review, call rest instead of ending the conversation. Then use the returned token with the response tool until the user resumes or the tool returns a terminal response.
[[/tool]]

Browser-dialog tools in this group are intended for macOS/Windows. Desktop notifications work across macOS, Windows, and Linux.

[[group:file]]
--- File operations -----------------------------------------------------------

File operations are for individual files and local filesystem objects.

[[tool:read_file]]
read_file:
- Use line ranges, head/tail, or max_bytes to keep context focused.
- Use ranges for several non-contiguous snippets from the same file.
- Binary files return summaries by default; request base64 only when bytes are required.
[[/tool]]

[[tool:write_file]]
write_file creates or fully overwrites a file. Prefer surgical editing when that capability is available. Request show_diff=true only when you actually need a unified diff in the result.
[[/tool]]

[[tool:append_to_file]]
append_to_file is only for additive writes. Do not use it when existing content needs to change.
[[/tool]]

[[tool:edit_file]]
edit_file is the default editing tool for existing files:
- Add enough surrounding context to old_str so the intended occurrence is unique.
- Use batch edits for multiple replacements in the same file.
- Use dry_run for risky replacements or unclear matches.
- Use replace_all only when every occurrence is intentionally in scope.
[[/tool]]

[[tool:delete_file]]
delete_file deletes a single file or symlink irreversibly. For directories, use the directory deletion tool when that group is available.
[[/tool]]

[[tool:copy_file]]
copy_file copies either one file or one directory tree. Be careful with overwrite=true because destination content is replaced.
[[/tool]]

[[tool:move_file]]
move_file moves or renames either one file or one directory tree. Be careful with overwrite=true because destination content is replaced.
[[/tool]]

[[tool:get_file_info]]
get_file_info returns metadata, and can include line counts when count_lines=true. Use it before targeted reads in large files or when you need size/type/permission facts.
[[/tool]]

[[tool:path_exists]]
path_exists is the cheapest existence/type check for a single path.
[[/tool]]

[[tool:diff_files]]
diff_files compares two text files without shelling out and guards large/binary inputs.
[[/tool]]

[[tool:calculate_checksum]]
calculate_checksum verifies identity or integrity for one or more files.
[[/tool]]

[[tool:create_symlink]]
create_symlink creates symbolic links; on Windows it may require Developer Mode or elevated privileges.
[[/tool]]

[[tool:compress_files]]
compress_files creates zip/tar/tar.gz archives. Use it instead of shell archivers for cross-platform behavior.
[[/tool]]

[[tool:extract_archive]]
extract_archive unpacks zip/tar/tar.gz archives. Use it instead of shell archivers for cross-platform behavior.
[[/tool]]

[[group:multi]]
--- Batch file operations -----------------------------------------------------

Multi-file tools exist to reduce round trips and avoid flooding context.

[[tool:read_multiple_files]]
read_multiple_files reads 2+ files in one call. Use it for related small/medium files after narrowing with search tools when possible; set per-file caps when files may be large, and keep the batch bounded with total_max_bytes. For exploratory repo work, prefer ranges, head, or tail over many full-file reads. It can also expand root+glob in one round trip.
[[/tool]]

[[tool:write_multiple_files]]
write_multiple_files writes 2+ files in one call. Leave show_diff=false for broad generated writes unless per-file diffs are important.
[[/tool]]

[[tool:find_replace_in_files]]
find_replace_in_files performs project-wide or directory-wide replacement:
- Always run with dry_run=true first.
- Narrow scope with glob and exclude_patterns.
- show_diff defaults to false; enable it only for narrow replacement sets, or combine it with max_total_diff_bytes.
- Use show_unmodified only when you need an audit trail; otherwise it creates noise.
[[/tool]]

[[tool:path_exists_batch]]
path_exists_batch checks many paths at once. Prefer it over repeated single-path checks.
[[/tool]]

[[tool:get_multiple_file_info]]
get_multiple_file_info returns metadata for many paths. Line counts are opt-in with count_lines=true.
[[/tool]]

[[tool:delete_files]]
delete_files deletes multiple file or symlink paths in one call.
[[/tool]]

[[tool:copy_paths]]
copy_paths copies multiple files or directory trees in one call.
[[/tool]]

[[tool:move_paths]]
move_paths moves multiple files or directory trees in one call.
[[/tool]]

[[group:dir]]
--- Directory operations ------------------------------------------------------

[[tool:list_directory]]
list_directory returns detailed directory entries with sizes and modification times. Use it for one-level inspection or bounded recursive listings.
[[/tool]]

[[tool:directory_tree]]
directory_tree returns a compact visual structure. Use it to understand a project layout before selecting files to inspect.
[[/tool]]

[[tool:create_directory]]
create_directory creates missing parent directories and is a no-op if the target already exists.
[[/tool]]

[[tool:delete_directory]]
delete_directory removes directories. Empty deletion is straightforward; force=true recursively deletes the entire tree and should be treated as destructive.
[[/tool]]

Listing tools cap output by default. If output is truncated, narrow with max_depth, glob, and exclude_patterns before raising max_entries. Use max_entries=0 only when you truly need everything.

[[group:search]]
--- Search --------------------------------------------------------------------

[[tool:search_files]]
search_files finds paths by name. Use it when you know a filename, extension, glob, or partial path.
[[/tool]]

[[tool:grep_files]]
grep_files searches file contents. Use it for symbols, function names, TODOs, errors, strings, and config keys.
[[/tool]]

Search defaults are intentionally conservative:
- Patterns are literal by default. Set use_regex=true for Go regex syntax such as |, ., *, +, ^, $, or character classes.
- Use glob to include relevant file types.
- Use exclude_patterns to prune noisy basenames such as .git, node_modules, dist, build, vendor, logs, or generated output.
- Use output_mode="files_with_matches" or "count" when matching lines would be too noisy.
- Use path_format="absolute" only when relative paths are ambiguous.

[[group:exec]]
--- Shell and environment -----------------------------------------------------

[[tool:get_working_directory]]
get_working_directory returns OS, hostname, cwd, and a compact environment summary. Call it early when local path or OS assumptions matter.
[[/tool]]

[[tool:run_command]]
run_command is a bounded, non-interactive command runner:
- Use it for build/test/lint commands, project scripts, version control inspection, or operations not covered by purpose-built tools.
- Set cwd explicitly when the command must run in a specific project directory.
- Pick the shell that matches the syntax: sh/bash for Unix syntax and heredocs; powershell/pwsh for PowerShell syntax; cmd for simple Windows cmd commands.
- cmd /C does not understand Unix syntax, heredocs, $VAR, or single-quoted strings.
- Prefer repo-native wrappers such as make targets when a workflow spans multiple file types, and keep formatter invocations language-specific.
- No PTY is allocated. Avoid interactive shells, TUIs, pagers, editors, curses apps, and full-screen prompts unless they have a non-interactive mode.
- Use stdin for scripted input.
- Use raw_output=true when you need parseable stdout/stderr without command metadata.
- Use allow_nonzero_exit=true when non-zero status is expected and you still need the output.
- Use detach=true for long-running servers or watchers; monitor them with process tools if available.
[[/tool]]

[[tool:open_in_app]]
open_in_app opens a file, directory, or URL in the default system app. Use it instead of shell-specific open/start/xdg-open commands.
[[/tool]]

[[tool:get_env]]
get_env reads environment variables. Without key/filter it lists names only to avoid leaking secrets. Secret-like values are redacted by default.
[[/tool]]

[[group:system]]
--- System --------------------------------------------------------------------

[[tool:http_request]]
http_request is for HTTP APIs and small/medium text responses:
- It supports common HTTP methods, headers, basic auth, request bodies, redirects, and timeouts.
- JSON is compact by default; use json_format when you need pretty or raw JSON.
- Use body_filter for large text responses when you only need matches, matching lines, or counts.
- Prefer a dedicated download tool, when available, for binary files or large downloads.
[[/tool]]

[[tool:download_file]]
download_file streams a URL directly to disk and creates parent directories. Prefer it over assembling large or binary downloads manually.
[[/tool]]

[[tool:clipboard_read]]
clipboard_read accesses the system clipboard and is capped by default so large clipboard contents do not flood context.
[[/tool]]

[[tool:clipboard_write]]
clipboard_write places text on the system clipboard.
[[/tool]]

[[tool:list_processes]]
list_processes inspects running processes. Use filter to find servers/watchers you started and command_width when commands are truncated.
[[/tool]]

[[tool:get_system_info]]
get_system_info returns a compact CPU, memory, and disk snapshot.
[[/tool]]
